# Prototype Matt, MCP, and update-channel resolution

Type: prototype
Status: open
Blocked by: 12, 13

## Question

Does a throwaway resolver fixture for the Matt Pocock distributions and the
currently repeated Context7, Firecrawl, GitHub, Greptile, and Chrome DevTools
MCPs produce understandable provider choices, component controls, conflicts,
operation dispositions, generated overlays, and lock diffs before the
production implementation is designed in detail? For representative native
plugin routes, can the adapter suppress background updates and restore an exact
artifact version; when it cannot, does the fixture retain an explicit
native-rolling restore class and an `operator_action` or `unavailable`
disposition instead of claiming immutable convergence?
