Issue #211 · logic prototype

Public documentation architecture

A goal-first map for learning, adopting, operating, integrating, auditing, and recovering the release-trust system without mixing documentation modes or authority boundaries.

Disposable architecture only

Question this prototype answers

Can one page catalog route eight audiences through the complete release lifecycle by immediate goal, keep every page in one primary Diataxis mode, and put the owning contract, authority boundary, version applicability, next step, and recovery route where each reader needs them?

This file is an information-architecture model, not a documentation site or security control. It opens locally, keeps all state in memory, and makes no automatic network request. It contains no production configuration, credentials, keys, host data, provider resource, trust anchor, or executable cryptography. Page titles, metadata fields, paths, and command references are prototype candidates, not compatibility or support promises.

Start with the reader’s goal

Diataxis type remains visible, but it never becomes the only navigation. A reader chooses what they need to accomplish or understand first.

Ownership and versioning model

      
“Owning page” means the canonical documentation home for a fact or workflow. It never grants cryptographic or operational authority.

      

        

          
Normative reference

          
The public core owns schemas, lifecycle rules, invariants, error classes, extension rules, and adapter interfaces. Reference mirrors their exact versions and is generated where the source permits. A prose edit cannot redefine them.

        

        

          
Tutorials and how-to guides

          
Documentation maintainers own reader flow. Each page names the exact contract, profile, fixture corpus, adapter, and qualification record it applies to. Before 1.0, no page invents a compatibility window, release cadence, backport, or support promise.

        

        

          
Profiles and adapters

          
A policy-profile publisher owns public profile meaning. An adapter owner owns provider-specific configuration. Qualification evidence binds exact versions and environments; ownership, conformance, qualification, and support remain separate.

        

        

          
Private adoption

          
The adopter owns deployment bindings, real resource identifiers, secret references, host procedures, ceremonies, and acceptance evidence in its own repository. Public docs provide value-free templates and boundaries, never those values.

        

        

          
Consumers

          
The generic project documents verification and the independent-admission interface. Each protected consumer owns its stricter acceptance, archive, receipt, installation, and updater gates. Generic success never becomes consumer authority.

        

        

          
Immutable documentation bundles

          
Each public-core release can carry an immutable documentation bundle tied to its source revision and contract inventory. A presentation alias may route humans to a selected bundle, but every page displays exact applicability and archived bundles make no current-support claim.

        

      

    


    

      
Required navigation graph

      
These edges are release gates. Writers may add useful links, but they may not remove the path that owns a safety decision.

      

        

          
Verification failure

          
verify → error reference → trust, revocation, or freshness explanation → incident triage. A rejected or indeterminate result never links to a bypass.

        

        

          
Rotation fork

          
Every rotation page branches before action: normal lifecycle → rotate; factor-only loss → replace factor; suspected exposure → freeze, preserve evidence, and enter compromise response.

        

        

          
Ceremony and provisioning

          
Before an irreversible step, link to the active profile, custody reference, evidence requirements, and recovery rehearsal. The guide stops at any separately controlled authority boundary.

        

        

          
Publication gates

          
At each gate, link to schema, DNS/cache rules, monitoring, higher-generation rollback, and emergency response. An ambiguous effect routes to reconciliation, never blind retry or provider fallback.

        

        

          
Platform convergence

          
Linux and macOS installation remain separate how-to guides. Both converge on the same semantic qualification reference and shared verify, publish, and recovery workflows.

        

        

          
Provider separation

          
The Cloudflare tutorial stays branch-free and fixture-only. Vercel, GitHub, WKD, keyservers, alternate custody, and later providers enter through reference or focused adapter guides.

        

        

          
Independent consumer admission

          
Generic verification links to the consumer profile and its separate admission guide. Historical attribution never links directly to execution, installation, or promotion.

        

        

          
Incident precedence

          
Availability loss, infrastructure compromise, suspected signer exposure, and confirmed compromise remain distinct. The most restrictive applicable signed state wins; docs cannot restore positive authority.

        

        

          
Security reporting

          
Public reporting routes to the security policy before reproduction. Maintainer handling links triage, remediation, disclosure, qualification status, and independent fix verification without asking for secrets or live-system testing.

Executable examples and link checks

      

        

          
Example contract

          
Each executable block names an example ID, exact contract and profile versions, fixture case, expected stdout envelope, exit class, effect class, and created files. Illustrative snippets are labeled non-executable.

        

        

          
Fixture-only execution

          
Examples run later in an isolated, network-disabled, credential-free temporary environment against the structurally rejected fixture profile. They use synthetic .invalid names and public canary bytes only.

        

        

          
One source for expected results

          
Documentation imports requests, outputs, diagnostics, and negative cases from the conformance corpus. It does not copy and quietly fork them. Randomized signatures are checked semantically, not as regenerated byte-for-byte fixtures.

        

        

          
Generated reference

          
Schema fields, CLI options, machine results, error codes, capabilities, and compatibility rows derive from their versioned sources where possible. Handwritten framing links to generated facts instead of duplicating them.

        

        

          
Graph validation

          
A route manifest checks unique page IDs, valid internal targets, reachable goal starts, prerequisites, next and recovery edges, audience coverage, and required security paths. Anchor and local asset checks run on the built bundle.

        

        

          
#213 boundary

          
This architecture defines the metadata and outcomes documentation needs. The separate conformance ticket owns the runner, manifest syntax, fixture execution, determinism rules, and CI integration. This prototype does not start that work.

        

      

    


    

      
Documentation release gates

      

        

          
Diataxis and reader fit

          
Each page has one primary mode, audience, immediate need, and bounded job. Off-mode material has a named destination. Goal landing pages orient rather than expose a file list.

        

        

          
Source and version

          
Every fragile fact names its owning contract and exact applicability. Generated reference matches its source. Unresolved CLI, schema, package, path, provider, or support claims remain visibly deferred.

        

        

          
Authority and privacy

          
Security review confirms that docs neither create authority nor soften a failed gate. Public artifacts contain no deployment binding, credential, factor handle, provider locator, recovery layout, private hostname, or production trust value.

        

        

          
Examples

          
Every executable example uses an exact disposable fixture, expected result, and effect assertion. No example needs network, hardware, provider access, production keys, or a mutable trust store.

        

        

          
Links and lifecycle coverage

          
Internal targets, anchors, next and recovery links pass. Required verification, rotation, ceremony, publication, platform, consumer, incident, and vulnerability-reporting paths are reachable from goal navigation.

        

        

          
Qualification and review

          
Commands and platform/provider procedures cite current qualification evidence. Authority-boundary changes require the owning contract, ADR, threat-model review, conformance change, and maintainer approval before docs describe them as accepted.

        

        

          
Bundle integrity

          
The built documentation bundle records source revision, contract inventory, example results, generated-reference inputs, route-manifest digest, link result, privacy result, and reviewer disposition.

        

        

          
Emergency carveout

          
An authorized freeze or withdrawal never waits for presentation or documentation readiness. An emergency docs update may explain accepted state; it cannot bypass independent verification or grant positive authority.

        

        

          
Pre-1.0 honesty

          
No page promises a cadence, backport, compatibility window, advance notice, deprecation window, platform term, remediation deadline, or support level that the project has not explicitly adopted.

Later documentation build frontier

      

        
The architecture is ready; the full page set is not.

        
The next documentation build may create goal landing pages, shared metadata, templates, the route manifest, and contract-derived reference once the public repository shape and exact interfaces exist. Full tutorials and operational guides wait for their exact package names, CLI and schema versions, qualified adapters and platforms, stable fixture corpus, and the separately owned executable-example contract.

        
The minimal-adapter tutorial remains deferred unless one fixture-backed path can stay branch-free. No site publication, production adoption, provider provisioning, or conformance implementation belongs to this prototype.
