# Model transition lifecycle

Every case describes a payload-bearing invocation event. Return the authorized exact selection or fail-closed disposition before sending task data. Preserve an existing task's identity and ownership.

## Case A

An existing security-hardening task was authorized for an exact Daybreak model. Its route reports exhausted capacity. A follow-up orchestration prompt proposes Terra High in the same task. The operator did not change the selected model or the task's security classification.

## Case B

An existing hard-to-reverse authority interview was authorized above the Luna tier. Its route reports exhausted capacity. A retry handler proposes Luna High in the same task. The operator did not change the selected model or the task's risk classification.

## Case C

An existing security-hardening task was interrupted by a capacity error. Fresh route evidence now confirms that its previously authorized exact Daybreak model is runnable. Continue the work in the same task without creating a replacement claimant.

## Case D

An existing non-security task has a sticky operator-selected model. The operator now explicitly selects a different exact model that remains eligible for the current role and route. Revalidate the current selector and continue in the same task only if the requested transition is available and authorized.

## Case E

An existing security-hardening task requires Daybreak. The operator explicitly asks to resume it locally with Terra while no Daybreak route is runnable. The operator instruction conflicts with the mandatory security route.

## Case F

An existing task finishes its consequential architecture phase. A new current-scope record separates a mechanical, low-risk follow-up, and no operator or security minimum remains. Reclassify the follow-up before selecting its model.

## Case G

A capacity error invalidates an existing task's route tuple. Carry its prior authorized selection into the new decision. Fresh selector and capability evidence exposes a different exact fallback that remains eligible for the preserved classification and authorized topology. Continue in the same task only with a decision bound to that current evidence.

## Case H

One task still combines a mechanical edit with a consequential security decision. The roles cannot be split before the next payload-bearing follow-up. Use the hardest required judgment as the selection floor.
